# 插件性能优化（0.9.1）

## 测速结果

2026-09-06，Windows、Python 3.12，同一工作目录及知识包存储环境，在能够读取全部草稿的正常文件权限下，对比已安装的 0.9.0 引擎与工作区 0.9.1 引擎。每项执行两次，以下为平均墙钟时间，包含 Python 启动和输出收集。文件系统缓存已预热，数值不代表其他电脑或首次冷启动的保证。

| 只读后台操作 | 0.9.0 | 0.9.1 |
| --- | ---: | ---: |
| catalog：198 道题 | 3.769 秒 | 0.813 秒 |
| show c.pointer.swap-01 | 3.734 秒 | 0.827 秒 |
| packs inbox-list：50 条草稿 | 13.373 秒 | 1.318 秒 |

集中审核复测前后均返回 50 条 pending 草稿；不能使用因文件权限错误而跳过指纹读取的返回时间作为正常审核测速结果。

这些是后台命令测速，不是实际点击按钮的端到端录像计时。UI 回归测试另行确认开始、评测、提交及进度监听不会额外调用 catalog。测速不提交答案、不编译用户练习、不触发下载或云端任务。

## 改动

1. 使用 scandir 提供的文件元数据，逐层检查目录项，拒绝链接及 Windows reparse points 后才遍历子目录；减少重复解析每个文件的所有父目录。
2. load_pack_snapshot 单次计算载荷文件哈希，题库标识和审核指纹复用这份结果；load_pack 原有双返回值接口不变。
3. inside 每个路径节点只做一次 lstat；统一 Windows DOS/UNC 与 extended-length 路径的等价拼写，避免并发创建缓存目录时误报越界。真实越界和设备命名空间不会被放行。
4. 课程目录保存在插件内存中。学习进度独立通过 VS Code 文件接口读取，不启动 Python、不重建测试项；删除进度文件正常显示空进度，解析或权限错误保留上次状态。
5. 文件监听采用 150ms 防抖及串行刷新队列，完整刷新优先于进度刷新。加载过程中收到新变动会补读，不会丢失变动。
6. 去除开始/评测流程的重复刷新，避免未变化的课程面板反复重载；保留作答草稿、忙碌状态和提交防重机制。

## 安全边界

没有引入跨请求的文件哈希/mtime 缓存。题库每次后台加载仍重新读取并计算载荷哈希，包括大小和修改时间都相同的内容篡改。安装包索引校验、审核指纹、离线包校验、旧版本回退、代码信任和云端 Docker 验证流程均保留。知识包格式、题目 ID、学习进度格式不变。

模型推理、网络下载、GitHub Actions 排队以及 C/C++ 编译耗时不由本次刷新优化消除。
